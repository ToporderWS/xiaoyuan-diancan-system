### 3.1 表结构要点

| 表 | 关键约束 |
| --- | --- |
| `users` | `uk_users_phone(phone)` 唯一；`idx_users_nickname`、`idx_users_created_at`；`avatar` 默认 `default_user.jpg` |
| `admin_user` | `uk_admin_user_admin_name(admin_name)` 唯一 |
| `food_category` | `uk_food_category_cat_name` 唯一；`idx_food_category_sort(sort,is_show)`；`CHECK is_show IN(0,1)` |
| `food` | `fk_food_category(cat_id) → food_category(id)` **ON DELETE RESTRICT**；`CHECK price>=0 / stock>=0 / sales>=0 / is_sale IN(0,1)`；`price DECIMAL(10,2)` |
| `orders` | `uk_orders_order_no` 唯一；`fk_orders_user → users(id)` RESTRICT；`idx_orders_status_created(order_status,created_at)`；`CHECK order_status IN(0,1,2,3,4)` |
| `order_item` | `fk_order_item_order → orders(id)` **ON DELETE CASCADE**；`CHECK count>0 / food_price>=0`；`food_name`/`food_price` 为**下单快照** |
| `cart` | `uk_cart_user_food(user_id,food_id)` 唯一（保证同菜品不重复行）；双 FK CASCADE；`CHECK count>0` |
| `notice` | `idx_notice_show_time(is_show,publish_time)`；`CHECK is_show IN(0,1)` |

## 4. Flask 后端

| 项 | 值 |

| 依赖 | `requirements.txt`：Flask 3.1.0、Flask-Cors 5.0.0、PyMySQL 1.1.1、PyJWT 2.10.1、APScheduler 3.11.0、Werkzeug 3.1.3、python-dotenv 1.0.1、cryptography 44.0.0、pytest 8.3.4、requests 2.32.3 |

### 4.1 核心实现机制

| 机制 | 实现方式 |
| --- | --- |
| **数据访问** | 轻量 PyMySQL 连接池（`max_size=16`，线程安全）；请求级连接挂在 `flask.g`，`teardown_appcontext` 统一**提交 / 回滚 / 归还** |
| **事务** | `Database.transaction()` 上下文管理器；订单创建全过程在一个事务内 |
| **鉴权** | `jwt_required(role)` 装饰器 + `student_required` / `admin_required` 语义化封装；JWT `{id, role, exp}`；**角色不落库** |
| **密码** | Werkzeug `generate_password_hash`（默认 scrypt）/ `check_password_hash` |
| **统一返回** | `success/error/page_data`；`json.dumps(default=_default)` 处理 `Decimal` / `datetime` |
| **异常兜底** | `register_error_handlers`：`BizError` / `HTTPException` / 兜底 `Exception` **全部转 JSON**，永不返回 HTML 错误页 |
| **参数校验** | `validators.py` 统一 `require_* / optional_* / clamp_keyword / parse_page`，`keyword` 服务端截断防超长串 |
| **图片上传** | 扩展名白名单 + MIME + **文件头 Magic Bytes** 三重校验 + ≤2MB + UUID 随机文件名 + `realpath` 防路径穿越；文件名与上传目录做前缀校验 |
| **超时取消** | APScheduler `BackgroundScheduler` 每 60 秒执行 `auto_cancel_expired_orders()`：扫描「`created_at` 早于 15 分钟前且 `order_status=0`」的订单 → 事务内取消 + 按明细恢复库存；**启动即跑一次**，**纯数据库驱动，重启生效** |
| **防超卖** | 事务内 `SELECT ... FOR UPDATE` 锁定 `food` 行 + 条件扣减 `UPDATE food SET stock=stock-n WHERE id=? AND stock>=n`（双保险） |
| **金额** | MySQL `DECIMAL(10,2)`，Python 全程 `Decimal`，核心金额**禁用 float** |

### 4.2 订单号规则

`CO` + `yyyyMMddHHmmss`(14 位) + 随机 4 位 + 序号 3 位 = **23 位**，`orders.order_no` 唯一键保证不重复。

## 8. 补充接口逐条说明（7 个，仅管理员端）

**补充原因**：后台 9 个页面均需**列表查询**与**详情查看**能力，而原始 18~28 组只有「新增/编辑/删除/状态流转」**写接口**，缺少对应**读接口** —— 若不补充，管理员新增菜品后无法回显、订单无法查看详情，后台不可用。

**补充边界（严格遵守）**：① 只补读接口，**不新增任何写能力**（仅管理员头像上传除外，且与既有上传校验完全复用）；② 不改 8 张冻结表、不加第 9 张表、不加字段；③ **不做原需求未授权的能力**：不提供管理员修改/删除学生账号、不提供管理员修改学生购物车、不提供 `admin_name` 修改。

| # | 方法 | 路径 | 为什么必须补充 |
| --- | --- | --- | --- |
| 补充 1 | GET | `/api/admin/category/list` | 学生端 `food/category/list` 只返回 `is_show=1`；后台必须能看到并管理**被禁用的分类** |
| 补充 2 | GET | `/api/admin/food/list` | 学生端 `food/list` 只返回**已上架**菜品；后台必须能看到并重新上架**已下架**菜品，且需展示库存/销量等管理字段 |
| 补充 3 | GET | `/api/admin/order/detail` | 接单/完成前必须看到收货地址与明细；学生端 `order/detail` 有归属校验，管理员无法复用 |
| 补充 4 | GET | `/api/admin/notice/list` | 公开 `notice/list` 只返回 `is_show=1`；后台看不到被隐藏的公告，也无法分页搜索 |
| 补充 5 | GET | `/api/admin/cart/list` | 需求要求后台存在「购物车管理」页；为守边界本接口**只读**，**不提供修改/删除学生购物车** |
| 补充 6 | GET | `/api/admin/info` | 个人中心需回显管理员信息；登录接口只在登录瞬间返回一次，刷新后无回显来源 |
| 补充 7 | POST | `/api/admin/upload_avatar` | 个人中心要求支持管理员改头像；**仅允许改头像**，不提供 `admin_name` / `real_name` 修改 |
