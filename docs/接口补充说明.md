# 接口补充说明

> 适用工程：`backend/`（Flask）
> 对应版本：V1.0
> 生成日期：2026-09-29

本文件逐条列出**交付实现中的全部接口**，并单独说明**新增补充接口的触发原因、契约与权限**。

---

## 一、总体约定

| 项 | 约定 |
| --- | --- |
| API Base URL | `http://192.168.0.103:5000/api` |
| 图片静态路径 | `http://192.168.0.103:5000/static/upload/` |
| 统一返回体 | `{ "code": 200, "msg": "文本", "data": {} }` |
| 成功码 | `200` |
| 参数/业务错误 | `400` |
| 未登录 / Token 失效 / 角色不匹配 | `401` |
| 服务异常 | `500` |
| 鉴权请求头 | `Authorization: Bearer {token}` |
| JWT Payload | `{ id, role, exp }`；`role=0` 学生、`role=1` 管理员 |
| 角色存储位置 | **仅 JWT**。`users` / `admin_user` 表均**不存在 `role` 字段** |
| 异常兜底 | 已注册全局异常处理器，**任何异常都不会返回 Flask 的 HTML 错误页**，一律转 JSON |

接口总数：**28 组原始接口**（学生端 17 组 + `17A` 模拟支付 = 18 个端点；管理员端 18~28 共 11 组，其中 4 组各含新增/删除两个端点 → 15 个端点）+ **7 个最小必要补充接口**（仅管理员端）。

另有 **2 个非业务端点**（`GET /`、`GET /api/health`），不列入业务接口清单。

## 二、学生端接口（1 ~ 7，账号相关）

### 1. `POST /api/user/register` — 学生注册

- **权限**：公开（无需 Token）
- **请求体**：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `nickname` | string | 是 | ≤ 50 |
| `phone` | string | 是 | 中国大陆手机号（`1[3-9]\d{9}`），全局唯一 |
| `password` | string | 是 | 6 ~ 64 |
| `student_no` | string | 否 | ≤ 30 |
| `dormitory` | string | 否 | ≤ 100 |

- **返回**：`data` 为学生信息（**不含任何密码或哈希**）
- **说明**：密码经 Werkzeug `generate_password_hash()` 入库；手机号重复返回 `code=400`。

### 2. `POST /api/user/login` — 学生登录

- **权限**：公开
- **请求体**：`phone`、`password`
- **返回**：`{ token, user_id, nickname, phone, avatar, student_no, dormitory }`
- **说明**：`token` 的 JWT `role=0`；手机号不存在与密码错误返回**同一提示**，避免账号枚举。

### 3. `GET /api/user/info` — 获取当前学生资料

- **权限**：学生 Token
- **返回**：`id / phone / nickname / avatar / student_no / dormitory / created_at`
- **说明**：`id` 取自 Token，**不接受前端传入 user_id**，天然免疫越权。

### 4. `POST /api/user/update_info` — 修改资料

- **权限**：学生 Token
- **请求体**：`nickname`（必填）、`student_no`、`dormitory`
- **说明**：**不允许修改手机号**（手机号为登录账号，且表结构冻结）；本次提交的 `dormitory` 会更新默认收货地址。

### 5. `POST /api/user/update_pwd` — 修改密码

- **权限**：学生 Token
- **请求体**：`old_password`、`new_password`（6 ~ 64）
- **说明**：校验原密码；成功后前端需重新登录。返回文案为「密码修改成功，请重新登录」。

### 6. `POST /api/user/upload_avatar` — 上传头像

- **权限**：学生 Token
- **请求方式**：`multipart/form-data`，字段名 `avatar`（兼容 `file`）
- **校验**：扩展名白名单（`jpg/jpeg/png/webp`）+ MIME + 文件头 Magic Bytes + ≤ 2MB
- **返回**：`{ avatar: "文件名" }`
- **说明**：UUID 随机文件名；**数据库只存文件名**；前端用 `STATIC_BASE + filename` 拼接。

### 7. `POST /api/user/logout` — 退出登录

- **权限**：学生 Token
- **说明**：**V1.0 已知限制** —— 数据库冻结为 8 张表、不新增 Token 黑名单表，服务端**不吊销 JWT**，仅返回成功；登出为客户端行为（清除本地 `student_token`）。

## 三、学生端接口（8 ~ 9，菜品浏览）

### 8. `GET /api/food/category/list` — 分类列表

- **权限**：公开（无需 Token）
- **返回**：`{ list: [{ id, cat_name, sort, is_show }] }`
- **说明**：只返回 `is_show=1` 且按 `sort` 升序。

### 9. `GET /api/food/list` — 菜品列表

- **权限**：公开（无需 Token）
- **Query**：`cat_id`、`keyword`、`page`、`page_size`（默认 10，上限 100）
- **返回**：`{ list, total, page, page_size, pages }`
- **说明**：只返回 `is_sale=1` 且所属分类 `is_show=1` 的菜品；`keyword` 服务端截断长度（`clamp_keyword`）防超长串攻击。`stock=0` 时前端展示「售罄」。

## 四、学生端接口（10 ~ 12，购物车）

> 三个接口全部要求**学生 Token**，`user_id` **一律取自 Token**，不接受前端传入。

### 10. `GET /api/cart/list` — 购物车列表

- **返回**：`{ list, total_count, valid_count, total_amount }`
- **说明**：每一项带 `valid` 标记 —— 菜品下架 / 已删除 / 库存不足时 `valid=false`，并给出原因；`total_amount` 只累计 `valid=true` 的小计，`Decimal` 计算。

### 11. `POST /api/cart/save` — 加入购物车

- **请求体**：`food_id`、`count`（1 ~ 999，为**本次增加的数量**）
- **返回**：该购物车项
- **说明**：`cart` 表对 `(user_id, food_id)` 建唯一键，**已存在则累加**；累加后若超过库存返回 `code=400` 且不写入。

### 12. `POST /api/cart/del` — 移出购物车

- **请求体**：`cart_id`
- **说明**：删除前校验该 `cart_id` 的 `user_id` 是否等于 Token 中的 `id`，**越权删除返回 `code=400`**（IDOR 防护）。

## 五、学生端接口（13 ~ 17A，订单）

### 13. `POST /api/order/create` — 提交订单

- **权限**：学生 Token
- **请求体**：`receive_address`（必填，≤ 120）、`remark`（≤ 200）
- **冻结契约**：**结算当前购物车全部有效商品，不做部分勾选结算**。
- **事务与一致性**：
  1. 开启事务 → 校验购物车非空（空车返回 `code=400`）
  2. 逐项 `SELECT ... FOR UPDATE` 锁定 `food` 行
  3. 校验上架状态与库存
  4. 条件扣减 `UPDATE food SET stock = stock - n WHERE id = ? AND stock >= n`（双保险）
  5. 写入 `orders` + `order_item`（`food_name` / `food_price` 为**下单时刻快照**）
  6. 清空该学生购物车 → 提交
- **价格**：`total_price` **完全由后端按数据库价格计算**，忽略前端任何金额。
- **订单号**：`CO + yyyyMMddHHmmss(14) + 随机4位 + 序号3位`，共 **23 位**，`orders.order_no` 建唯一键。
- **说明**：任一步失败整体回滚，**不会出现扣了库存却没有订单**的情况。

### 14. `GET /api/order/my_list` — 我的订单列表

- **权限**：学生 Token
- **Query**：`order_status`（0~4，可空）、`page`、`page_size`
- **返回**：`{ list, total, page, page_size, pages, status_text_map }`
- **说明**：只返回 Token 中 `id` 的订单；`status_text_map` 便于前端统一渲染状态文案。

### 15. `GET /api/order/detail` — 订单详情

- **权限**：学生 Token
- **Query**：`order_id`
- **说明**：先校验订单归属，**越权访问他人订单返回 `code=400`**；明细通过 `LEFT JOIN food` 补齐 `food_img` 供前端展示图片。

### 16. `POST /api/order/cancel` — 取消订单

- **权限**：学生 Token
- **请求体**：`order_id`
- **状态机**：**仅 `0 待支付` / `1 待接单` 可取消**；`2 配送中`、`3 已完成`、`4 已取消` 一律拒绝（`code=400`）。
- **库存**：取消时按 `order_item` 逐项**恢复库存**；**重复取消不会重复恢复**（状态必须仍为 0/1 才执行）。

### 17. `GET /api/notice/list` — 公告列表

- **权限**：公开（无需 Token）
- **返回**：`{ list }`，**只返回 `is_show=1`**，最多 20 条，按 `publish_time` 倒序。

### 17A. `POST /api/order/pay` — 模拟支付

- **权限**：学生 Token
- **请求体**：`order_id`
- **状态机**：**仅允许 `0 → 1`**，同时写入 `pay_time`；重复支付返回 `code=400`。
- **说明**：**不接入真实微信支付**。前端 UI 必须明确标注「模拟支付」。已超时被自动取消的订单不可支付。

## 六、管理员端接口（18 ~ 28）

> 除 `18. /api/admin/login` 外，**全部要求管理员 Token**。学生 Token 调用一律 `code=401`。

### 18. `POST /api/admin/login` — 管理员登录

- **权限**：公开
- **请求体**：`admin_name`、`password`
- **返回**：`{ token, admin_id, admin_name, real_name, avatar }`
- **说明**：JWT `role=1`；账号来源为 `admin_user` 表（由 `scripts/init_admin.py` 初始化，**`database.sql` 不含任何管理员明文密码**）。

### 19. `GET /api/admin/dashboard` — 控制台统计

- **返回**：
  - **4 张统计卡**：学生用户总数、今日新增订单、今日成交金额、在售菜品数
  - **折线图**：最近 7 天每日订单数（7 个数据点）
  - **柱状图**：各分类销量（真实聚合 `food` × `order_item`）
  - **饼图**：订单状态占比（5 个状态）
- **说明**：**全部为真实数据库聚合，零 Mock**。「今日成交金额」只统计**今日创建且已支付（`order_status ≥ 1`）**的订单，不含已取消订单。

### 20. `GET /api/admin/user/list` — 学生用户列表

- **Query**：`keyword`（昵称 / 手机号 / 学号 / 宿舍）、`page`、`page_size`
- **说明**：**只读**，不提供管理员修改 / 删除学生账号的接口（原需求未授权）。

### 21. 分类管理（21a / 21b）

- **21a `POST /api/admin/category/save`**：`{ id?, cat_name, sort, is_show }`。`id` 缺省为新增，存在为编辑（**同一端点承担新增与编辑**，与需求「分类保存」一致）。`cat_name` 唯一。
- **21b `POST /api/admin/category/del`**：`{ id }`。**分类下存在菜品时删除被拒**（`code=400`），避免产生孤儿菜品；外键 `ON DELETE RESTRICT` 同样兜底。

### 22. 菜品管理（22a / 22b）

- **22a `POST /api/admin/food/save`**：`{ id?, cat_id, food_name, price, stock, description, is_sale }`
  - 支持 `application/json`；**也支持 `multipart/form-data` 直接携带菜品图片**（字段名 `food_img`，兼容 `file` / `image`）—— 因此**不需要额外的菜品图片上传接口**
  - `price` / `stock` 校验非负；`price` 走 `Decimal`
  - **编辑时若未传新图片，保留原图**
- **22b `POST /api/admin/food/del`**：`{ id }`。删除时同步清理其图片文件；被 `order_item` 引用时依赖外键约束保护。

### 23. `GET /api/admin/order/list` — 订单列表

- **Query**：`order_status`、`keyword`（订单号 / 收货地址）、`start_date`、`end_date`、`page`、`page_size`
- **返回**：`{ list, total, page, page_size, pages, status_text_map }`
- **说明**：日期范围按 `created_at` 的日期部分过滤。

### 24. `POST /api/admin/order/receive` — 接单

- **请求体**：`order_id`
- **状态机**：**仅允许 `1 → 2`**；其他状态返回 `code=400`。

### 25. `POST /api/admin/order/finish` — 完成订单

- **请求体**：`order_id`
- **状态机**：**仅允许 `2 → 3`**，同时写入 `finish_time`。
- **销量**：按 `order_item` 明细累加 `food.sales`；**重复完成不会重复累加**（状态必须仍为 2 才执行）。

### 26. 公告管理（26a / 26b）

- **26a `POST /api/admin/notice/save`**：`{ id?, title, content, is_show }`；`id` 缺省为新增，存在为编辑。
- **26b `POST /api/admin/notice/del`**：`{ id }`。

### 27. `POST /api/admin/update_pwd` — 修改管理员密码

- **请求体**：`old_password`、`new_password`（6 ~ 64）
- **说明**：仅修改密码。**`admin_name` 不提供修改入口**（原需求未授权）。

### 28. `POST /api/admin/logout` — 管理员退出登录

- **说明**：同学生端第 7 条，**V1.0 不吊销 JWT**，由前端清除本地 `admin_token`。

## 七、新增补充接口（7 个，仅管理员端）

### 补充原因

后台 9 个页面（用户 / 分类 / 菜品 / 购物车 / 订单 / 公告 / 个人中心）均需**列表查询**与**详情查看**能力，但原始需求 18~28 组接口中只提供了「新增/编辑/删除/状态流转」类**写接口**，缺少对应的**读接口**。若不做补充，管理员新增菜品后无法回显、订单无法查看详情，后台功能不可用。

补充**严格遵循**以下边界：

1. **只补读接口**，除「管理员头像上传」外**不新增任何写能力**；
2. **不改动 8 张冻结表**，不新增第 9 张表，不加字段；
3. 不做原需求**未授权**的能力：**不提供管理员修改/删除学生账号、不提供管理员修改学生购物车、不提供 `admin_name` 修改**。

### 补充 1. `GET /api/admin/category/list`

- **权限**：管理员 Token
- **返回**：`{ list }` —— **含 `is_show=0`（禁用）的分类**
- **为什么需要**：`GET /api/food/category/list` 是学生端公开接口、只返回启用分类。后台分类管理页必须能看到并管理**被禁用的分类**，故单独提供。

### 补充 2. `GET /api/admin/food/list`

- **权限**：管理员 Token
- **Query**：`cat_id`、`keyword`、`page`、`page_size`
- **返回**：`{ list, total, page, page_size, pages }`
- **为什么需要**：学生端 `GET /api/food/list` 只返回**已上架**菜品。后台必须能看到并重新上架**已下架**菜品，且列表需展示库存、销量等管理字段。

### 补充 3. `GET /api/admin/order/detail`

- **权限**：管理员 Token
- **Query**：`order_id`
- **返回**：订单主体 + **下单学生信息** + 订单明细（含 `food_img`）
- **为什么需要**：接单 / 完成前必须看到收货地址与明细；学生端 `GET /api/order/detail` 有归属校验（只能看自己的订单），管理员无法复用。

### 补充 4. `GET /api/admin/notice/list`

- **权限**：管理员 Token
- **Query**：`keyword`、`page`、`page_size`
- **返回**：`{ list, total, page, page_size, pages }`
- **为什么需要**：公开接口 `GET /api/notice/list` **只返回 `is_show=1`**，后台无法看到被隐藏的公告、无法重新显示，也无法分页搜索。

### 补充 5. `GET /api/admin/cart/list`

- **权限**：管理员 Token
- **Query**：`keyword`（学生昵称 / 手机号）、`page`、`page_size`
- **返回**：`{ list, total, page, page_size, pages }`（含所属学生与菜品信息）
- **为什么需要**：需求要求后台存在「购物车管理」页面。为守住授权边界，本接口**只读**，**不提供管理员修改 / 删除学生购物车**的能力。

### 补充 6. `GET /api/admin/info`

- **权限**：管理员 Token
- **返回**：`{ id, admin_name, real_name, avatar, created_at }`
- **为什么需要**：个人中心需要回显当前登录管理员信息。管理员登录接口只在登录瞬间返回一次，刷新页面后缺少回显来源。

### 补充 7. `POST /api/admin/upload_avatar`

- **权限**：管理员 Token
- **请求方式**：`multipart/form-data`，字段名 `avatar`（兼容 `file`）
- **返回**：`{ avatar: "文件名" }`
- **为什么需要**：个人中心页面要求支持管理员修改头像，与校验规则（扩展名 / MIME / 文件头 / 2MB / UUID 文件名）**完全复用** `utils/uploader.py`。
- **边界**：**仅允许修改头像**，不提供 `admin_name` 或 `real_name` 修改接口。
