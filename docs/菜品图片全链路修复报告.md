## 1. 根因是什么

**根因不在上传/显示代码，而在数据语义。**

演示数据脚本 `backend/scripts/seed_demo.py` 第 78 行把**兜底占位图的文件名硬写进了数据库**：

```python
(cur|food_name, price, stock, 'food-default.jpg', desc)   # ← 旧代码
```

导致 12 个演示菜品的 `food.food_img` **全部等于 `'food-default.jpg'`**：

```
id=1  小笼包套餐   food_img='food-default.jpg'
id=2  手抓饼加蛋   food_img='food-default.jpg'
...                                   （共 12 行）
id=12 烤肠        food_img='food-default.jpg'
```

于是前端按"这是一个真实文件名"去拼地址 `STATIC_BASE + food-default.jpg`，**如实显示了那张粉色占位图**。链路本身是通的，所以"所有菜品都是同一张图"看起来像 Bug，实际是**占位图被当成了真实值写进库**。

**次生缺陷（本轮一并修掉）：**

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 2 | `utils/uploader.py` 的 `delete_uploaded_image()` 只保护 `default_user.jpg`，**未保护 `food-default.jpg`** | 编辑菜品换图时会把**全站共享**的菜品占位图物理删除，其它未设置图片的菜品立刻全部裂图 |
| 3 | 前端只有"空值兜底"，**没有"加载失败兜底"** | 图片文件丢失/网络异常时 `<image>` 空白（不白屏但有裂图） |
| 4 | `admin-pc/src/config.js` 用 `127.0.0.1`，与小程序用的局域网 IP 不统一 | 与"地址集中统一"要求不符 |
| 5 | `miniprogram/scripts/check-project.js` 会把 `unpackage/`（HBuilderX 编译产物）当源码扫描 | 自检**假报错**（编译后的第三方代码含 TODO 字样、地址已被内联） |
| 6 | `backend/scripts/e2e_check.py` 里**硬编码** `http://127.0.0.1:5000/static/upload/` | 用局域网 IP 地址跑 E2E 时静态资源检查必然假失败 |
| 7 | 小程序头像空值时复用了**菜品**占位图 | 头像兜底错用了美食图 |
